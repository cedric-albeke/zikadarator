## Fixed During This Audit

The Windows CI package path previously diverged from the documented local package and assembled ZIP/installer payloads before signing. It also passed a VST3 bundle directory to `signtool` instead of the plugin binary.

The corrected pipeline now:

1. Signs the VST3 binary and standalone executable before staging when a certificate is present.
2. Fails if a certificate is supplied but signing cannot be completed.
3. Uses `scripts/package-windows-release.ps1` in CI and local packaging.
4. Builds the installer from the same root-level package tree shipped in the ZIP.
5. Records signed/unsigned status inside package build metadata.
6. Checksums the included Inno Setup source.
7. Extracts the final ZIP and runs its checksum verifier before upload.
8. Creates CI build metadata before artifacts are uploaded.

The macOS CI ordering defect is also corrected at source. Developer ID bundle signing and strict verification now happen before package staging; the staged copies are verified again before ZIP/PKG creation. The final installer is then signed, optionally submitted to Apple notarization, stapled, and validated before SHA-256 generation. `BUILD-INFO.txt` records signing and notarization separately, and both it and `SHA256SUMS.txt` are created and verified before upload. A source regression enforces this ordering. The unsigned tester path is now proven on a real runner; Apple identities, package installation, and the notarization service path still require a credential-backed run.

The first real macOS-14 run built both test binaries successfully and passed all engine tests, then exposed a headless test-harness assumption: JUCE's `runDispatchLoopUntil()` did not deliver the CRT timer message without an application/window runloop. The regression now retains the normal dispatch attempt and falls back to `Timer::callPendingTimersSynchronously()` only after real timer intervals elapse, testing registration and repeated 30 Hz callbacks without depending on platform window dispatch.

The follow-up macOS-14 run passed CTest plus VST3 and AU pluginval at strictness 5, but the separate system `auval -v` could not yet discover the copied component through Apple's global registry. A registry-instrumented third run proved that the component was present and healthy as `aumf/Zkfx/Zika`; the validator had incorrectly assumed the `aufx` type. The validation install now clears the per-user Audio Unit cache, restarts `AudioComponentRegistrar`, performs bounded discovery retries, and requires `auval -a` to list that exact emitted identity before targeted validation. This preserves a hard failure for real registration defects while eliminating both the registry race and the stale type assumption.

The final unsigned macOS-14 run, [Actions run 29888007903](https://github.com/cedric-albeke/zikadarator/actions/runs/29888007903) at commit `e6d454f`, completed in 15m12s. Engine and processor CTest, universal VST3/AU/Standalone builds, VST3 and AU pluginval at strictness 5, exact system `auval`, package staging, ZIP/PKG construction, metadata/checksum creation, and all five artifact uploads passed. The downloaded `ZIKADARATOR-macos.zip` and `ZIKADARATOR-Installer.pkg` matched the published SHA-256 values. `BUILD-INFO.txt` correctly labels them `UNSIGNED - tester build only` and `NOT NOTARIZED`; the signed/notarized branch was skipped because repository secrets are not configured.

## UI/UX Correctness Gate

The previously confirmed baseline keyboard/accessibility gap is closed at source and regression-test level. Custom-drawn header actions now expose stable names, help text, deterministic global focus order, Space/Enter parity, and exactly-once tab switching. Preset buttons expose the full effect name and description instead of relying on icon paint and hover tooltips. Custom knobs are focusable sliders with visible focus rings, ranged value interfaces, arrow/Home/End operation, and balanced host gestures for keyboard and accessibility-client edits. The StepGrid is announced as one six-by-sixteen keyboard-navigable group; its 96 visual child cells are intentionally excluded from duplicate focus traversal while the group reports and announces the selected lane, step, active state, and preset. Child controls can no longer bubble unhandled keys into destructive grid commands, and only the actual focused control receives a focus ring. Footer sliders and custom modulation/resolution buttons now expose purpose- and slot-specific names.

Advanced keyboard parity is now complete. Page Up/Down cycles the selected step's preset, while Shift+Left/Right shortens or extends a tie after resolving consumed cells back to their root. The commands preserve the mouse paths' undo and editor notification contracts, refuse to extend across an active step, clamp at grid boundaries, and are announced in the StepGrid accessibility help. Direct regressions cover preset movement, root resolution, tie resizing, collision protection, callback counts, and the existing focus-ownership guard.

The wider UI correctness slice is complete: Presets and Settings now reflow into dedicated rows and two-column control groups, the standalone JUCE device selector is clipped inside a scrolling viewport, chain-badge painting and hit testing share one geometry source, and the duplicate footer `STEP RES` paint call is removed. JUCE geometry tests cover Presets and Settings at 1184x718 and 900x600, and desktop screenshots verified the standalone layouts at approximately 1200x858 and 922x671. Lane mix knobs now use a bidirectional JUCE parameter attachment, follow message-thread and asynchronous host automation plus preset restore, and emit balanced host gestures for drag, click, double-click reset, keyboard/accessibility edits, and editor destruction during a drag with direct regressions. StepGrid drag-to-paint now copies active presets or erases from inactive sources across every interpolated cell, keeps APVTS gates synchronized with complete host gestures, normalizes host-enabled blank sources, breaks overwritten chains cleanly, and reserves Shift+Drag for ties. Direct mouse-event regressions cover copy, erase, tie, Shift-click without drag, click-only selection, chain conflicts, and one undo boundary per gesture. Waveform taps now discard queued samples whenever their UI consumer is hidden, both page and visibility directions clear retained history, and fixed 16,384-sample UI scratch buffers keep the 30 Hz drain ahead of common high sample rates without allocation. Lock-free operation guards prevent host reprepare from racing producer/consumer access, while tap generations invalidate display history after sample-rate resets. The CRT monitor owns a targeted 30 Hz repaint timer, so scanline and phosphor motion no longer depend on unrelated header events.

## Confirmed DSP And State Gaps

The source-audited V1 runtime no longer exposes a known preset-name/engine mismatch. Scratch, vinyl, granular, and formant-preserving stretch remain intentionally deferred rather than represented by substitute DSP.

The realtime scratch-memory gate is complete. `prepareToPlay()` now establishes a minimum fixed scratch capacity and prepares every engine against that same maximum segment size. Hosts may deliver larger blocks without resizing: `processBlock()` walks them in prepared-capacity chunks while preserving PPQ continuity, waveform capture, mono/stereo behavior, immutable sequencer state, and segment scheduling. Global, lane mix, mute, solo, and step-active parameters are cached as stable atomic pointers during construction, so the audio callback no longer constructs lane IDs or searches APVTS. A 4097-sample regression after a declared 64-sample prepare proves exact chunk count, unchanged scratch capacity, and sample-accurate dry output across the full oversized block; source guards reject scratch resize/assign calls and realtime APVTS lookup.

The host-transport identity gate is complete. Scheduler segments retain signed absolute steps alongside modulo-16 grid steps, including bounded extreme positions and negative preroll. The processor compares both host sample time and PPQ against the previous external block end with a strict two-sample tolerance, and advances an onset generation on clock-domain changes, stop/start, loop/seek discontinuities, or step-resolution changes. Slice, Loop, and Filter identity includes that generation, absolute chain origin, root grid step, and preset, so chains trigger once while the same modulo step in another cycle or after an in-place preset change retriggers. State restore requests onset invalidation atomically for the audio thread instead of writing its identities from the message thread. Stopped callbacks freeze sequenced engines without consuming onset state while retaining output gain and bypass for live monitoring; free clock remains continuous. Scheduler-safe chunk sizing prevents the fixed 64-segment stack batch from collapsing later offline steps. Direct regressions cover continuous callbacks, sample and PPQ loops, large tempo changes, monotonic sample time with looping PPQ, 16-step seeks, stop/restart output, negative and extreme positions, host/free switching, bypassed seeks, state restore, chained boundaries, preset/resolution changes, all three onset-driven lanes, and 1,280 step boundaries in one offline block.

Invalid host sample rates are normalized to 44.1 kHz before any engine, gain/pan state, waveform tap, or scratch storage is prepared. Regressions cover zero, sub-10 Hz, NaN, and infinity through an active pitch lane, plus preservation of a valid 96 kHz request.

The first DSP/state slice is complete. `SliceEngine` now receives resolved host/free-clock BPM every block, with separate 60-versus-120 BPM render regressions for free clock and a simulated JUCE host playhead. APVTS is the canonical realtime step-active gate through cached atomic parameter pointers; sequencer metadata, exported snapshot state, StepCell visuals, chains, and header state synchronize without discarding preset or chain data. Factory presets now use JUCE's actual `PARAM` child-tree format, mirror every sequencer gate, and explicitly reset lane mix/mute/solo state, while versioned migration preserves unversioned patterns. Wrong-root host state is rejected before sequencer loading, and state export no longer mutates the live sequencer. Automated Off-to-On transitions inside the current step now have direct behavioral coverage for SLICE retriggering, LOOP history playback, and FILTER reconfiguration. `EnvFollowerEngine` now applies bipolar mapping with direct engine coverage.

The second DSP/state slice is complete. Concurrent message-thread sequencer writers now serialize live-grid changes and snapshot publication; synchronized live getters return values, while audio reads remain lock-free. LOOP and SLICE pin trigger history and copy it into preallocated playback storage incrementally, bounded to 2,048 frames or the current scheduler-chunk size. Pending playback starts immediately from the pinned ring history, capture is serviced before later writes can overwrite it, and SLICE history retains all 16 offsets at the prepared 20 BPM floor. Direct regressions cover concurrent snapshot coherence and maximum 192 kHz capture budgets.

The FILTER realtime-cost slice is complete. All processor filter paths now submit cutoff and resonance together, reducing the former double coefficient rebuild to one deduplicated update. Type coefficients update only on type changes, 12 dB modes skip the unused second stage, and Comb delay/feedback math is cached outside sample rendering. The Comb delay uses preallocated generation-tagged stereo storage, so transitions logically clear history in constant time rather than zeroing the complete delay line in the callback. Regressions cover update counts, unchanged-value deduplication, and stale-history isolation after a Comb transition.

The LOOP/preset-contract slice is complete. LOOP history now retains 12 seconds, which covers the full four-beat user range at the 20 BPM floor; the eight-beat maximum tail explicitly communicates its 12-second cap. FX1 Comb/Notch sweeps and FX2 Filter/Delay/Pitch/Bitcrush paths use matching names and vector icons rather than Phaser, Tonalizer, Vinyl, Stretch, Grain, or Chaos symbols. FILTER presets 12-20 now apply bounded cutoff/resonance tunings, eliminating duplicate aliases. Direct tests cover the history boundary and distinct tuning behavior, while source guards enforce the runtime naming/icon contract.

Recommended next product slice: decide the V1 factory-preset count, then close installed Ableton and credential-backed macOS release validation before changing version metadata. The advanced StepGrid keyboard and unsigned macOS runner gates are closed.
